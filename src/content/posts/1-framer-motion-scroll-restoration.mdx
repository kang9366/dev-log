## 발생 배경

브라우저는 최적의 사용자 UX를 위해, 상세 페이지에서 **뒤로 가기**를 했을 때 이전 스크롤 위치를 자동으로 복원하는 `scrollRestoration` 기능을 제공합니다.

```js
// 브라우저 기본 동작
history.scrollRestoration // → 'auto'
```

그런데 **Framer Motion**의 `AnimatePresence`와 함께 사용하면 전환 애니메이션 중 스크롤 복원이 너무 이르게 실행되어 화면이 순간 튀는 현상이 발생합니다.

---

## 원인 분석

페이지 전환 타이밍을 시각화하면 다음과 같습니다.

| 시점 | 브라우저 | Framer Motion |
|------|---------|--------------|
| popstate 이벤트 | scrollRestoration 실행 | exit 애니메이션 시작 |
| 16ms 후 | 스크롤 위치 복원 완료 | exit 애니메이션 진행 중 |
| 300ms 후 | — | enter 애니메이션 완료 |

브라우저가 스크롤을 복원하는 시점(`16ms`)이 Framer Motion의 exit 애니메이션이 끝나기 전이라, **이전 페이지가 사라지는 도중에 스크롤이 점프**하게 됩니다.

---

## 해결책 — Double rAF 패턴

`requestAnimationFrame`을 두 번 중첩해 브라우저의 스크롤 복원이 **한 프레임 이상 지연**되도록 합니다.

```ts
// scrollRestorationFix.ts
export function deferScrollRestoration(callback: () => void) {
  // rAF를 두 번 중첩해 브라우저 paint 이후로 지연
  requestAnimationFrame(() => {
    requestAnimationFrame(() => {
      callback()
    })
  })
}
```

### 적용 방법

```tsx
// Router 설정에서 scrollRestoration을 수동으로 제어
import { useEffect } from 'react'
import { useLocation } from 'react-router-dom'
import { deferScrollRestoration } from './scrollRestorationFix'

export function ScrollRestorer() {
  const location = useLocation()

  useEffect(() => {
    // 브라우저 자동 복원 비활성화
    if ('scrollRestoration' in history) {
      history.scrollRestoration = 'manual'
    }

    // 수동으로 지연 복원
    const savedY = sessionStorage.getItem(`scroll-${location.key}`)

    if (savedY) {
      deferScrollRestoration(() => {
        window.scrollTo({ top: parseInt(savedY), behavior: 'instant' })
      })
    } else {
      deferScrollRestoration(() => window.scrollTo(0, 0))
    }

    // 이탈 전 스크롤 위치 저장
    return () => {
      sessionStorage.setItem(`scroll-${location.key}`, String(window.scrollY))
    }
  }, [location.key])

  return null
}
```

## 왜 Double rAF인가?

단일 `rAF`만으로는 부족한 이유가 있습니다.

- **첫 번째 rAF**: 현재 프레임의 나머지 작업이 큐에 남아 있음
- **두 번째 rAF**: 이전 프레임이 완전히 commit된 이후 — 이 시점에서 스크롤을 복원하면 Framer Motion exit 애니메이션과 겹치지 않음

```
Frame N:   popstate 이벤트 발생
Frame N+1: rAF 1 콜백 (아직 exit 애니메이션 중)
Frame N+2: rAF 2 콜백 ← 여기서 scrollTo 실행 ✅
```

## 마무리

Framer Motion과 브라우저 API의 충돌은 **타이밍 문제**입니다. `sessionStorage`로 스크롤 위치를 수동 관리하고, Double rAF로 복원 타이밍을 한 프레임 늦추는 것만으로 깔끔하게 해결할 수 있습니다.
